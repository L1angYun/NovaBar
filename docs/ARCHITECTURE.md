# NovaBar 架构

本文描述 `0.4.3` 的默认运行路径，并说明另行启用的共享 GPU 纹理试验。试验路径不随安装默认开启，原生动画仍有对齐限制。

## 组件与线程

| 组件 | 职责 |
|---|---|
| `NovaBar.exe` | WinUI 3 配置编辑、近似预览、导入 / 导出、托盘、自启与更新界面 |
| `NovaBar.Engine.exe` | 读取配置、采集窗口状态、决策与发布外观、后台连接 XAML 宿主、监督捕获子进程 |
| `NovaBar.Capture.exe` | 在单一 MTA 中管理共享 WGC / D3D11 设备和来源池，合成场景、预处理画布，按请求类型发布 BGRA 帧或共享纹理元数据 |
| `NovaBar.XamlBridge.v043.dll` | 在目标所属 UI 线程应用外观、读取帧并计算当前面板边带光学，默认更新 WriteableBitmap / ImageBrush |

桥接层通过系统 XAML 诊断接口订阅目标可视树。目标按宿主、根类型和背景元素识别；各目标保存自己的 UI 调度器。弱引用、订阅撤销与更新版本检查用于避免旧目标或旧外观覆盖当前状态。Normal 恢复原始本地属性，原值未设置时清除本地覆盖。

AppContainer 宿主所需桥接文件暂存在其包 LocalState 中，继承已有权限。接入不依赖 SYSTEM 服务或全局 COM 注册。构建与打包不会自动重启外壳。

## 配置与进程间通信

```text
配置中心 → 配置 / 应用通道 → Engine → 外观状态 → XAML 桥接层
                                              ↓ 几何与来源请求
                                      独立 Capture 进程
                                              ↓ 双缓冲 BGRA（默认）
                                      XAML 桥接层呈现
```

持久配置位于 `%APPDATA%\NovaBar\settings.json`。外观、请求、帧响应与诊断通道位于 `%LOCALAPPDATA%\NovaBar` 或对应宿主的应用数据目录。Engine 支持 `--data-dir` 隔离通道。

配置文件采用临时文件替换；读取失败保留最后一次有效配置。桥接身份与版本化 DLL 文件名统一定义在 `src/NovaBar.Shared/BridgeIdentity.h`。请求与帧校验进程所有权、目标身份、协议、尺寸、几何及来源时效；仅在这些条件兼容时接受新帧或复用已有画布。

`--restore` 发布持续生效的恢复状态。重新应用配置解除恢复状态；退出配置中心不等于退出 Engine。

## 状态与规则

状态优先级为：省电 > 任务视图 > 搜索 > 开始菜单 > 窗口状态 > 桌面。禁用的直接状态继续回退；禁用界面或恢复请求使用 Normal。

窗口规则先匹配实际状态的专用组，再匹配通用组。组内按进程名、标题、类名依次进行不区分大小写的包含匹配。状态和规则均可保留独立非活动外观。忽略列表排除参与决策的候选窗口。

各界面的配置与输出通道分离。TTB 导入保留有窗口、最大化各自的规则，不将两组互相覆盖。

## 真实场景与像素路径

```text
真实窗口 / 桌面 WGC 纹理
    → Capture：GPU 场景合成
    → Capture：GPU 基础模糊 / 色调 / 噪声，或支持条件内的任务栏条带光学
    → 最终 BGRA 回读与双缓冲传输
    → 面板客户端 CPU 当前边带光学
    → WriteableBitmap / ImageBrush 上传与 XAML 合成
```

可见目标按其顶层窗口的实际下层 Z 顺序选取来源。隐藏的世界画布可按当前可见窗口顺序准备打开后的场景，并排除自身宿主的视觉窗口；切换可见性后重新按实际下层顺序求值。窗口区域、预乘 Alpha、全局透明度、颜色键和物理屏幕坐标共同决定合成结果。

只有完整、真实且仍有效的场景才能发布 Ready。所需窗口只有元数据、尚无可用图像时保持 Waiting；实际捕获错误报告 Unavailable。桌面可以是场景的一部分，但不能用桌面或静态壁纸填补缺失的应用窗口。GPU 路径失败时，CPU 回退同样必须重新取得完整真实场景；后端切换会触发重绘。

面板基础画布只包含模糊、色调和噪声，客户端按当前几何计算有限边带的折射、色散与高光。任务栏保留独立条带光学；GPU 条带路径不满足物理一比一、非平铺等条件时使用真实 CPU 路径。

共享 GPU 纹理试验仅供显式启用的面板使用。预处理画布经同一适配器上的共享 D3D11 纹理和围栏传输，客户端复制到私有 GPU 纹理，在 GPU 上计算光学并提交合成纹理。传输只映射帧元数据，不回读整幅画布；发布下一帧之前确认当前帧已复制，等待期间合并场景变化。可见面板在渲染回调复用已验证的元数据映射，来源轮询负责刷新请求、映射和拥有权。此试验未启用时，仍使用上述默认路径。

首次取得真实来源前保持透明。等待后续图像时，可在来源时效与请求有效性约束内继续使用同一真实画布；明确不可用时立即撤下，来源失效、请求或帧过期、进程退出时也撤下液态画面。LiquidGlass 不自动回退 Acrylic 或系统模糊；Acrylic 是独立选择的材质。

## 调度与恢复

捕获进程使用 QPC 计算工作预算和剩余等待，并优先使用高分辨率可等待计时器，不修改系统全局定时器分辨率。可见目标优先轮转；到期隐藏目标使用独立轮转并保留防饥饿机会。隐藏世界画布限制更新频率；预热不能绕过来源完整性或所有权检查。

面板当前几何与有限边带更新由所属 UI 线程的 XAML 渲染回调驱动。来源读取、来源发布、UI 回调和最终屏幕呈现是不同阶段，其频率不能互相替代。

共享设备移除时报告错误并结束捕获进程，由 Engine 监督重新创建设备与来源池。目标销毁、尺寸变化和分配失败均保留撤下、重建或重试路径。

## 安装与更新

安装程序以当前用户权限部署自包含应用和匹配的原生组件。应用内更新只使用项目发行源，下载与安装分开确认，检查大小与 SHA-256，并在启动安装程序前重新校验。更新保留配置及更新前的引擎运行 / 恢复状态；卸载先恢复外观。

首次创建通知宿主的接入等待，以及部分原生独立动画中的背景对齐，仍属于已知限制。默认路径包含 CPU 处理、GPU 回读和 XAML 上传，不能描述为端到端全 GPU 或固定屏幕帧率。测试范围见 [PARITY.md](PARITY.md)。
